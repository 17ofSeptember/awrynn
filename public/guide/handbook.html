1. The claim, and how to test it

The engine is written from scratch, with no TensorFlow.js, no ONNX and no autodiff library. Forward pass, backpropagation, optimizers and regularization are plain TypeScript over Float64Array, and every number the interface shows is read back from that engine rather than recomputed for display.

That is an easy thing to claim and a hard thing to earn, so here is how it is substantiated.

Analytic gradients are checked against numerical ones

The suite runs a full matrix, {linear, relu, leaky_relu, tanh, sigmoid} × {mse, bce, cce} × {with, without L2} × {2-1, 2-4-1, 2-8-6-3}, skipping invalid combinations, comparing every analytic gradient against a numerical estimate. 60 configurations, 2,379 parameters. Worst relative error: 1.09e-9 against a 1e-7 threshold.

Why not a plain central difference at a single ε? Central differences trade truncation error (∝ h²) against roundoff (∝ 1/h), so the best step size depends on |L|/|g| and no constant is right everywhere. At ε = 1e-5 the worst coordinate here reaches 1.44e-7 and fails, not because the gradient is wrong, but because float64 cannot resolve that difference. Richardson extrapolation cancels the h² term, so the step can stay large enough that roundoff never bites: R(h) = (4·D(h/2) − D(h)) / 3. Plain differences are kept as fallbacks, and win on ReLU, which is piecewise linear and needs no extrapolation.

The dissection is checked against the engine's own caches

Every formula card reads W, b, Z, A and dW out of the engine after a real forward/backward pass. The only value computed for display is the per-term product w·a, because the engine goes straight to a dot product and never materialises individual terms.

So that one computation is audited. Each neuron carries a residual: the sum of the terms as displayed, minus the z the engine actually cached. Across the full matrix the worst residual is under 1e-9, which is float reassociation and nothing more. A card showing arithmetic that did not add up would fail the test suite.

Determinism is bitwise

Same seed, same config, same number of steps ⇒ byte-identical parameter arrays. Asserted over 100 training steps by comparing raw bytes, not with a tolerance.

2. Conventions

Row-major batch convention throughout. Mixing conventions is the classic source of backprop bugs, so this is fixed.

SymbolShapeMeaning
X[B, n₀]Batch input, one row per sample
W⁽ˡ⁾[n_{l-1}, n_l]Layer weights
b⁽ˡ⁾[1, n_l]Biases, broadcast down the batch
Z⁽ˡ⁾, A⁽ˡ⁾[B, n_l]Pre-activations and activations
 
forward
Z⁽ˡ⁾ = A⁽ˡ⁻¹⁾ · W⁽ˡ⁾ + 1_B · b⁽ˡ⁾
A⁽ˡ⁾ = φ⁽ˡ⁾(Z⁽ˡ⁾)

backward
dZ⁽ˡ⁾   = dA⁽ˡ⁾ ⊙ φ′⁽ˡ⁾(Z⁽ˡ⁾)
dW⁽ˡ⁾   = (A⁽ˡ⁻¹⁾)ᵀ · dZ⁽ˡ⁾ / B     ← divided here
db⁽ˡ⁾   = colSum(dZ⁽ˡ⁾) / B          ← and here
dA⁽ˡ⁻¹⁾ = dZ⁽ˡ⁾ · (W⁽ˡ⁾)ᵀ            ← NOT divided
The divide-by-B convention. Unaveraged per-sample gradients propagate through the network; the division by B happens exactly once, when parameter gradients are formed. Divide in dA⁽ˡ⁻¹⁾ as well and every gradient picks up an extra 1/B per layer, which presents as "training is just slow" rather than as a bug. There is a test: a batch of two identical rows must produce the same gradients as a batch of one.

Fused output gradients

softmax + cce and sigmoid + bce are detected explicitly and take the analytically simplified path dZ⁽ᴸ⁾ = Ŷ − Y. Both cancellations remove a division by a quantity that goes to zero exactly when the network is confident, so the fused path is the numerically stable one as well as the fast one.

The unfused gradients are implemented too, purely so the test suite can verify the cancellation numerically, the softmax case against the full dense Jacobian, rather than taking the derivation on trust. The right panel reports which path a given configuration is on.

Validation, not silent fallback

softmax is legal only as the final activation and only with cce; bce requires a single sigmoid unit. Invalid combinations produce a written explanation in the architecture panel and the last good network stays on screen. Nothing is silently coerced.

4. Driving the dissection

Dissection in the bottom bar runs one sample through the network in slow motion. The choreography is a sequence of discrete beats rather than a continuous tween, which is what makes true single-stepping and prefers-reduced-motion fall out of the same structure. With motion reduced, the beats simply are the stages.

SpaceAdvance one beat. Mid-beat, the first press finishes the beat you were watching rather than skipping it.

Navigating the canvas without a mouse

Focus the canvas with Tab. Nothing inside a picture can take focus on its own, so the canvas takes it and interprets the arrow keys itself. Every move is announced to assistive technology, including the value, because position and colour carry the entire interface otherwise.

Columns do not wrap: the picture has a direction and the traversal respects it. A unit's own connections do wrap, since that is a short closed list you are deliberately cycling through.

Speed runs 0.1×–10× on a logarithmic slider, so 0.1× and 10× sit equidistant from 1×. The sample stepper wraps.

The beat sequence, for an L-layer network:

input
  → layer 1 weighted sum → layer 1 activation
  → …
  → loss
  → layer L δ → layer L ∂L/∂w → layer L update
  → …                                          (right to left)
  → complete
One deviation from a literal reading of the design. The choreography is specified "per neuron". On a 6-unit layer that means six 208px cards competing for a column whose nodes are ~64px apart, and they overlap into illegibility. So a layer resolves as a unit: the full card for one focused neuron, compact z / a chips for its neighbours, and clicking any node moves the focus. Every neuron still gets its card; you choose which one you are reading.

wRef is the 95th percentile of |w| across the network, smoothed exponentially over time. A percentile rather than the maximum, because one runaway weight would otherwise flatten every other edge to invisibility, which is exactly what happens right before a divergence, when the picture matters most. Its current value is printed in the legend.

Stroke width is a screen-space quantity and does not scale with zoom: the encoding must mean the same thing however far you have zoomed. Node radii do scale, because a node is an object in the scene rather than an encoding.

Colour-vision safety

The two poles were chosen so their OKLab separation increases under simulated deficiency rather than collapsing: 0.26 typical, 0.31 tritanopia, 0.36 protanopia, 0.43 deuteranopia, with both clearing 9:1 contrast on the canvas. The dash pattern in colourblind-safe mode is redundancy on top of that, not a rescue. Blue/red was rejected on these measurements; red/green was never a candidate.

6. Determinism

Math.random() does not appear anywhere in the engine, and the ban is enforced three ways: a TypeScript project that compiles the engine with no DOM lib and no ambient types, a test that scans the source tree, and an ESLint rule.

Randomness comes from mulberry32 seeded through a splitmix32 expansion, split into four independent named streams:

StreamUsed for
initWeight initialization
shuffleBatch shuffling and the train/validation split
dropoutDropout masks
dataDataset generation and noise

Streams are independent and order-insensitive: exercising dropout 500 times does not shift what init produces, and requesting them in a different order changes nothing. Turning dropout on therefore does not perturb your initialization, which is what makes an A/B comparison at a fixed seed meaningful.

The splitmix32 expansion exists because a raw seed like 1 has almost no entropy in its high bits, and nearby seeds would otherwise produce visibly correlated first draws. People type 1, 2, 3.

7. Sharing a network

Inspect → Share → Copy link produces a URL that rebuilds everything: the architecture, the dataset and its seed, every hyperparameter, the lesson you had open, and the weights. There is no server involved, and no account. The state is the link.

The state travels in the fragment, the part after the #. Browsers strip that before sending a request, so it never reaches a web server or an access log. A query string would have leaked the contents of your link to whoever is hosting the page, for no benefit at all.

Why some links have no weights in them

A link to a network you have not trained is short, around seven hundred characters, and contains no weights whatsoever. It does not need them. Initialization is seeded and bitwise deterministic, so the seed and the layer sizes regenerate exactly the same numbers on the other machine, down to the last bit.

The encoder does not assume this, it checks it. Before dropping the weights it builds a fresh network from the seed and compares the two parameter blocks byte for byte. If a single bit differs, because you trained, scrubbed a weight, or typed a value in, the weights are included and the link grows to around twelve hundred characters for a small network.

When they are included they are exact: float64, little-endian, no rounding and no compression. Halving the link by shipping float32 would mean the network you opened was not the network that was sent, and that is the one thing this project will not do. The panel tells you which kind of link you just made, and how long it is, since some chat clients truncate above about two thousand characters.

What a link does not carry

The loss curve. Open a link to a trained network and you get the trained weights and the carved decision boundary, but the epoch counter reads zero and the chart says there is no data yet. That is honest rather than broken: the sender's five hundred epochs of measurements are not in the link, and drawing a plausible curve nobody measured would be a fabrication. Press Train and it carries on from the weights you were sent.

Nor does it carry your undo stack, your pinned A/B snapshot, or your display preferences. Those are yours, not the network's.

The fragment stays in the address bar after the link opens, so you can bookmark it or copy it onward. That does mean reloading returns you to the shared network rather than to your own edits, but reloading already discards edits, so nothing is lost that would otherwise have survived.

8. Batch normalisation

The switch is in the Architecture panel and applies to the hidden layers, the same granularity dropout uses. Turning it on rebuilds the network, but costs you nothing: γ is filled with ones rather than sampled, so it never touches the initialisation stream, and W and b come back bit-identical at the same seed. Flipping the switch changes exactly one thing, which is what makes comparing its two sides worth anything.

Each normalised layer computes:

U = A · W                                  the weighted sum, no bias yet
Z = γ · (U − μ) / √(σ² + ε) + b        normalise, scale, shift

Where did β go?

Textbooks write the shift as β and drop the dense layer's bias. This implementation does the opposite and keeps the bias, because they are the same parameter. Adding a constant just before a step that subtracts the mean does nothing at all: shift every value in a column by δ and μ shifts by δ too, so U − μ is unchanged and the derivative with respect to b is identically zero.

So the bias moves rather than multiplying. It goes from before the activation to after the normalisation, which is exactly where β sits. It keeps its name, its bias satellite on the canvas and its line in the dissection card, and the layer gains one new parameter vector rather than two.

The part people get wrong

Training and evaluation are different functions. While training, a unit is normalised by the mean and variance of the batch it happens to be in, so its output depends on which other samples travelled with it. That is fine for learning and useless for predicting, so the layer also keeps a running average of those statistics and uses that instead once training is over.

This is why a network can post a training loss and a validation loss that disagree on identical data. It is not a bug and it is not overfitting: the two numbers were computed by two different functions. The dissection card tells you which of the two it used, and the inspector shows the running estimates alongside γ.

Two variances are involved, deliberately. The one that normalises the batch divides by B, because that is what makes the result have unit variance within the batch. The one that feeds the running average divides by B minus 1, because there it is estimating a population rather than describing a sample.

Small batches

A batch of one has no spread of its own. Normalising a single sample by its own statistics would map every unit to exactly zero and cut the gradient at that layer, silently, and the last batch of an epoch can easily hold one sample. So a batch of one is normalised by the running estimate instead, in training too, and contributes nothing back to it.

At a batch of two the normalised value is pinned to plus or minus one whatever the inputs do, which is worth knowing if you are experimenting: batch norm has very little to work with down there.

Checking it

The gradient check covers γ and runs the same matrix at batch sizes six, two and one. Turn on Dissection and step through a normalised neuron: the card shows the weighted sum, then the normalisation, then γ, then the bias, and the running total on the right reaches the engine's own z. The residual is checked across every unit, exactly as it is for a plain layer.

9. Numerical decisions worth knowing

  • float64 throughout. These networks have tens of parameters, so there is no memory argument for float32, and the gradient check needs the headroom.
  • Stable sigmoid. z ≥ 0 uses 1/(1+e⁻ᶻ); z < 0 uses eᶻ/(1+eᶻ). Neither branch ever exponentiates a positive argument.
  • Row-max-shifted softmax. Algebraically a no-op, but it caps the largest exponent at e⁰, so a logit of 1000 yields a probability instead of Infinity/Infinity.
  • Clamped logarithms. log(max(x, 1e-12)) everywhere. An unclamped log(0) destroys the loss curve even when the gradients are fine.
  • Momentum uses the accumulate-then-scale form (v ← μv + g; θ ← θ − ηv). The alternative folds η into the velocity and rescales the effective learning rate by 1/(1−μ).
  • Adam's bias correction is not optional. At t = 1 the corrected update reduces to exactly −η·sign(g) regardless of |g|; that cancellation is the signature of getting it right, and the test pins it there.
  • Freezing uses a skip mask, not a zeroed gradient. A momentum or Adam state carries a parameter forward on accumulated velocity even when its gradient is zero, so zeroing would let a "frozen" parameter drift.
  • L2 never touches biases. Asserted by comparing db bit-for-bit at λ = 0 and λ = 0.5.
A behaviour that surprises people. A tanh hidden layer with a fused sigmoid/bce output cannot diverge to NaN, at any learning rate. dZ = ŷ − y is bounded in [−1, 1] and tanh saturates, so the network stalls rather than exploding. To see a genuine divergence you need ReLU or an unbounded regression head. There is a test pinning this so it is not rediscovered the hard way.

10. What is and is not implemented

Implemented and tested:

  • Forward and backward passes; fused and general output paths
  • Activations: linear, relu, leaky_relu, tanh, sigmoid, softmax
  • Losses: mse, bce, cce
  • Initialization: Glorot uniform, He normal, LeCun normal, normal, uniform, zeros, constant
  • Optimizers: SGD, Momentum, Nesterov, RMSProp, Adam, AdamW
  • LR schedules: constant, step, exponential, cosine, composable warmup
  • L2, inverted dropout, gradient clipping by global norm
  • Batch normalisation, with separate training and evaluation statistics
  • Batching with a kept partial batch, stratified splits, standardization (with a deliberate-leak option)
  • Early stopping with best-weight restore; divergence as a reported state
  • Metrics: loss, accuracy, precision/recall, confusion matrix, per-layer gradient norms, dead units, saturation
  • Ten procedural datasets, including 7×5 glyphs
  • Training in a Web Worker, off the main thread
  • Canvas rendering, hit-testing, pan/zoom, and the dissection view

Also implemented, with an interface: live training with a loss curve, the decision boundary, per-neuron activation maps, the diagnostics panel, the live math tab, weight scrubbing, undo/redo, the history scrubber with an A/B weight diff, all twelve lessons, NumPy / JavaScript / PNG export, and URL-encoded shareable state.

Deliberately not implemented: three of the optional extensions were declined rather than skipped. A convolution demo and a recurrent network would each be a second architecture family with its own visual language, sharing a header with this one rather than belonging to it. WebGPU acceleration would put a GPU path behind a claim of plain float64 arrays, to speed up networks of a few hundred parameters that already train faster than you can watch. The other two, batch normalisation and shareable links, were built.

docs/MATH.md in the repository maps every equation to the function that implements it. docs/DESIGN.md is the token system and the reasoning behind the palette. docs/ARCHITECTURE.md covers the threading model and how the layers are kept apart.
