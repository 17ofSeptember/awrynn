1. What this thing actually is

A neural network is a machine for guessing. You give it some numbers, it does a lot of multiplying and adding, and out comes a guess.

That is genuinely all it is. There is no thinking inside it. The thing that makes it interesting is the second half: when its guess is wrong, it can work out which of its numbers to nudge, and in which direction, so that next time the guess is a little less wrong. Do that a few thousand times and the guesses get good.

Everything in AwryNN is that one idea, made visible. The app is not a diagram of a neural network. It is one, running in your browser, and every number you see on screen is a number it really computed.

The example we will use. The default screen shows a network learning to separate two interleaving crescent shapes, the moons dataset. Each dot in that dataset has two numbers (a left-right position and an up-down position) and belongs to one of two groups. The network's job is to look at the two numbers and say which group.

2. One neuron, completely

Every circle on the canvas is a neuron. A neuron does exactly three things, in order. Nothing else.

  1. It multiplies each incoming number by a weight. A weight is just a number the network stores. If a weight is large, that input matters a lot to this neuron. If it is near zero, that input is being ignored. If it is negative, that input pushes the neuron the other way.
  2. It adds all of those up, plus a bias. The bias is one more stored number, added on at the end regardless of the input. It shifts the neuron's whole response up or down. The running total is called z.
  3. It squashes the total through an activation function. The result is called a. This step is what stops the whole network collapsing into something trivial. More on that below.

Written out, for a neuron with two inputs:

z = (weight₁ × input₁) + (weight₂ × input₂) + bias
a = squash(z)

Here is a real one, copied from the app's own display: 

Z  LAYER 2 · UNIT 0
   (+0.73)(−0.12)     −0.085
 + (+0.65)(−0.16)     −0.106
 + (−0.52)(+0.42)     −0.216
 + (−0.65)(+0.04)     −0.029
 + (−0.60)(−0.07)     +0.044
 + (−0.10)(+0.12)     −0.012
 + bias               +0.000
z =                  −0.4043

Six inputs, six weights, six products, added up, plus a bias of zero. Add the right-hand column yourself: it comes to −0.404. That is not a mock-up. That is the app showing its working.

Why the squashing step exists

Multiplying and adding is a straight-line operation. If you stack a hundred layers that only multiply and add, the whole stack still only draws a straight line, so you have gained nothing. The squashing function bends the result, and it is that bend, repeated across layers, that lets a network carve out curved and complicated shapes.

The default here is tanh, which takes any number and squeezes it into the range −1 to +1. Very negative in, close to −1 out; very positive in, close to +1 out; near zero in, near zero out.

The small circles marked b

Those are the biases, one per neuron, each drawn as its own little satellite. Most diagrams leave biases out entirely, which is why so many people come away believing a neuron is only a weighted sum. It is not. The bias is a real stored number and it is drawn here so you can see it and change it.

When you first load the app every bias is exactly zero, so those satellites and their connections look faint. That is honest: they have not learned anything yet.

4. Reading the colours

The whole app is built on one colour idea, and it only encodes one thing.

MarkMeaning
Cool blueA negative weight. This connection pushes the receiving neuron down.
Warm amberA positive weight. This connection pushes the receiving neuron up.
Thick lineA weight with a large value. This connection matters.
Faint hairlineA weight near zero. This connection is being ignored. Watch these fade out as a network learns which inputs are irrelevant.
Filled circleHow strongly that neuron is firing for the sample being shown.
Hollow circleA dead neuron. It has not fired once in a whole pass through the data. Usually a sign something has gone wrong.
Colour only ever means sign, and thickness only ever means size. Nothing else in the interface uses these two colours, so if you see blue or amber anywhere, it is telling you about a number's sign. Selections and highlights are deliberately plain white for exactly this reason.

5. Watch one number travel

This is the part worth doing slowly. Go to the app and press Dissection: off in the bottom bar to switch it on. Then press Space repeatedly. Each press advances one stage and stops.

  1. Inputs The two input circles light up and their values appear beside them. This is one single example from the dataset: one dot, two numbers.
  2. Layer 1: weighted sum Dots travel along the connections from the inputs into the first layer. A fat dot is a big contribution; a thin one is barely contributing. Its colour tells you whether it is pushing up or down.

    The size follows the contribution, meaning weight × input, not the weight on its own. A huge weight multiplied by an input of nearly zero contributes nothing, and it would be misleading to draw it fat.

    As each dot lands, its term appears on the card beside the neuron and the running total ticks over. You are watching a sum being built.
  3. Layer 1: activation The total z settles, and a small graph appears showing the squashing function. A dot travels along the bottom axis to where z sits, then rises to meet the curve. Where it lands is a, the neuron's output. The neuron then fills in to match.
  4. The same, layer by layer Each layer's outputs become the next layer's inputs. Finished neurons shrink to a compact z / a chip so you can still see what they settled on.
  5. Loss A card appears with three numbers: what the network guessed, what the correct answer was, and a single number scoring how wrong it was. That score is the loss. Zero would be perfect. Bigger is worse.

Click any neuron to move the detailed card onto it. On a wide layer only one neuron shows its full working at a time, because six cards at once would be unreadable, so you pick which one you are reading.

6. How it learns

Keep pressing Space past the loss card and the animation reverses. It now flows right to left. This is backpropagation, and it is the only genuinely clever idea in the whole subject.

The question it answers is: for each of the network's stored numbers, would nudging it up make the loss better or worse, and by how much?

Answering that for one number is easy: try it and see. Answering it for all of them one at a time would be impossibly slow. Backpropagation gets the answer for every weight in one sweep backwards, by reusing work as it goes.

Here is a card from that sweep, again straight off the screen:

W[0, 0]
∂L/∂w = (+0.504)(−0.384)
      = −0.1932
Δw = −0.100 × ∂L/∂w = +0.0193

Line by line:

  • ∂L/∂w is unfriendly notation for a friendly idea: how much the loss changes when this one weight changes. It is called the gradient. Here it is −0.1932, meaning: increase this weight a little and the loss goes down a little.
  • So we should increase it. Δw ("delta w") is the change we actually make: +0.0193.
  • The −0.100 is the learning rate, meaning how big a step to take. Too small and learning crawls. Too big and it overshoots and flies apart. It is the single most important dial in the whole subject.

Then the connection visibly re-weights, and that is one learning step, for one weight, from one example. Real training does this for every weight, over and over, thousands of times.

Why the minus sign? The gradient points in the direction that makes the loss bigger. We want smaller, so we step the opposite way, hence Δw = −learning rate × gradient. That is the whole of "gradient descent": walk downhill by repeatedly stepping against the slope.

7. Five things to try

  1. Turn a weight up and watch nothing happen. Hover a hairline-thin connection and read its value in the inspector. Those near-zero weights are connections the network has decided not to use.
  2. Change every layer to linear. linear means "no squashing at all". The network becomes a plain straight-line machine, no matter how many layers you give it. This is the single best demonstration of why the squashing step exists.
  3. Press Reseed a few times. Every weight is re-randomised. Same shape, same data, completely different starting numbers, and if you trained it, a different solution each time. There is no single right answer inside a network.
  4. Switch the dataset to glyphs. Suddenly there are 35 inputs, one per pixel of a tiny 7×5 letter, and 10 outputs, one per possible answer. Nothing about the machinery changed. That is the whole leap from a toy to real image recognition.
  5. Step through the same sample twice. Identical numbers, every time. Nothing here is random once the seed is fixed, which is what lets you check the app's arithmetic against your own.

8. Every word, defined

WordMeaning
NeuronOne circle. Multiplies its inputs by weights, adds them plus a bias, squashes the result.
WeightA stored number on a connection. How much one neuron's output matters to the next.
BiasA stored number added on regardless of input. Shifts a neuron's whole response.
ParameterAny stored number: every weight and every bias. The right panel counts them.
LayerA column of neurons that all read the same inputs.
zA neuron's running total, before squashing.
aA neuron's output, after squashing. This is what travels onward.
Activation functionThe squashing step. tanh, sigmoid, relu and friends.
Forward passInputs to guess. Left to right.
LossOne number scoring how wrong a guess was. Lower is better.
GradientHow much the loss would change if one parameter changed. Written ∂L/∂w.
BackpropagationThe right-to-left sweep that computes every gradient in one go.
Learning rateHow big a step to take. Too big diverges, too small crawls.
EpochOne complete pass through all the training data.
SeedThe number that fixes all the randomness, so a run can be repeated exactly.
Dead neuronOne that never fires. Drawn hollow. Usually caused by too high a learning rate.
Batch normA switch that makes each layer rescale its numbers to a familiar size before passing them on, so the layer above is not learning against a moving target. Columns using it are labelled ·bn.
